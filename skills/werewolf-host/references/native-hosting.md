# 原生卡片主持

仅在用户明确选择不用狼人杀小程序时使用。不能与同一局的小程序流程同时运行。

你是独立主持人，不兼任玩家、不投票。玩家包括人类和其他 AI。规则由本局约定决定，不把某一种人数配置或胜负条件当成唯一玩法。

## 主持消息与所在群

整局在用户指定的现有群里进行。用户在私聊安排主持，也只是在向你下达指令；身份、行动、查验、投票和主持记录都发送到目标群。跨会话调用 sendInteractiveMessage 时明确填写目标群的 conversationId，不要遗漏后发到当前私聊。不为主持添加好友、创建玩家私聊或修改群成员。

身份和观众总览直接使用限定 message.audience 的普通文字消息，不要求回复“收到”或点击确认。身份只向对应玩家和主持人可见；观众总览只向用户指定的观众与主持人可见，不能向参赛玩家展示完整身份。行动提交和投票使用交互消息，主持记录用仅主持人可见的卡。规则说明、夜间口令和玩家自由发言使用普通消息，不要求所有消息都做成交互卡。

“天黑请闭眼，狼人请睁眼”等通用口令可公开发送，但不公开具体行动者的姓名或座位。狼人讨论必须限定为本局狼队、主持人和用户允许查看的观众可见；不能把讨论发成公开普通消息。先核对 sendGroupMessage 的实际 schema 是否支持可见成员；若不支持，不能把 @ 或交互卡标题当成私密普通消息，不声称已经进行了狼队私密讨论。

暂停与恢复工具用于目标群的玩家调度，可在私聊和群聊调用。在私聊主持时明确填写目标群的 groupId 和玩家 senderId；群聊省略 groupId 时使用当前群。不能用群内 @、另建私聊或改成员代替。发卡不等于玩家已经行动，只有真实提交及回调才能推进。

## 开局与保密

1. 用 readGroupChat 读取真实群成员及接话状态，确定主持人、玩家、座位顺序和旁观者。工具参数使用查到的成员 ID，界面和群消息只显示名字或座位号。
2. 优先沿用用户已给的规则；缺少会影响结算的配置时，一次询问人数与角色、屠边或屠城、平票、遗言、女巫自救及猎人触发条件。可以提出简洁方案供用户确认，不擅自开局。不要自动添加玩家或修改 AI 人设。
   若规则包含警长，开局同时确定上警、退水、竞选发言、警长投票资格及票权；未约定警长就不自行增加竞选环节。先确定用户本人是玩家还是观众，以及观众允许提前查看哪些信息，不因其是用户就公开所有秘密。
3. 保存开局前 AI 的接话状态。先 pauseGroupAutoReply 暂停本局其他 AI 玩家；主持人保持接话。对仍开启接话的旁观 AI，明确本局是否旁观并暂停，防止它随每条消息思考。
4. 每次任务涉及底牌、夜间行动、未公开投票且会展示思考过程时，先调用 hideThinking，再生成或读取秘密；没有可见思考过程时不用调用。它只隐藏本次任务后续思考，不能代替消息权限。
5. 公布冻结的规则，再随机分配角色。使用实际可用的代码执行工具随机打乱名单，并立刻保存结果；重试或恢复对局不得重新抽身份。不要把全部角色表输出到群里或放进项目共享记忆、共享文件。
6. 通过 sendGroupMessage 给每位玩家单独发身份说明，message.audience 只含该玩家和主持人；正文只写其身份、技能及应知信息，不要求玩家回复。狼人同伴名单只发给狼队及主持人。若用户要求观战总览，另发仅指定观众与主持人可见的完整身份消息。

## 持久记录

创建只对主持人可见的交互卡作为本局记录：audience=[主持人]，presentation=system，按钮用 notifyAi=false 的 acknowledge。记录规则、座位、角色、存活状态、天数和阶段、当前发言者、各卡片标识及轮次、事件处理进度、已结算的行动与投票，以及原始接话状态。底牌只留在此卡；公开状态另发简短群消息。

进入新任务先读本局记录及相关卡片，按当前 revision 更新，完成阶段后及时保存。发卡成功就记录返回标识；中断恢复时先核对现存记录和近期历史，不重复发身份、扣药、淘汰或开启新轮。工具报错不能当成操作成功；有无法确定的状态就暂停推进，向用户说明具体问题，不猜结果。

## 投票与行动回调

固定选项的行动和投票使用单个 submit 按钮，notifyAi=false；通过 participation.callbackEvents 注册事件监听，接入后自动接收，不再配置启用开关。投票不产生逐条系统回执，参与者从卡片确认提交。下面两种事件不需要 callbackEventId 确认，不要为它们写回同样的 title/body/buttons，不要让玩家等待 AI 确认。

- `vote`：实时回调，source=interactionVote，operationType=submit 或 change。用于记录收票、暂停刚提交的 AI、交给下一位。单人行动卡也可以只监听 complete；需要在多人行动完成前交接时才同时监听 vote。
- `complete`：结束回调，source=interactionComplete，completionType=conditionMet 或 manualClose；completionConditionMet 说明完成条件是否成立。用于读取最终结果、结算并进入下一阶段。

事件包含 messageId、eventId，以及操作数据中的 revision、round、sessionVersion、phase、submittedCount、summary；指定 actors 时有 eligibleCount。实时事件还包含 actorId、actorName。submission、choices 和共享 state 仅在接收者有权查看时提供；缺少这些字段不代表无人投票或提交失败。主持人始终可查看自己发起卡片的实时汇总，但读取个人行动仍需卡片授予相应权限。

按 messageId 与 round 找到本局阶段，按 eventId 记录处理进度；同一卡片同一轮的结束只结算一次。最后一票可能同时送来 vote 和 complete：vote 仅完成收票与玩家调度，不能宣布出局或扣药；phase 已不是 collecting 时不要再恢复下一位，交给 complete 结算。旧轮或已结算阶段的事件不能再次推进；恢复时读取当前卡片核对进度，不轮询、不重投。

manualClose 是提前停止收集的原因，不自动等于正常全票结束；即使关闭动作恰好满足完成表达式，也先按关闭原因和本局约定处理。缺票时不得直接拿现有票数宣布正常结果。用户取消对局或授权更改流程时，记录原因后关闭相关卡片；关闭产生的事件不能重新启动已经取消的阶段。工具失败保留原始报错，不仅因失败就重复原调用。

## 轮流发言与成本

pauseGroupAutoReply / resumeGroupAutoReply 调整自己时直接调用；主持人本身是群主时可直接调整其他成员，是管理员时可直接调整普通成员和其他管理员。普通成员调整其他普通成员须通过工具申请用户授权，已有对应 AI、目标群、目标成员和操作的授权时由系统判定是否可以复用。不能调整更高角色成员，也不能申请越权。senderIds/all 批量调度只供群主或管理员使用，普通成员不能通过申请获得批量管理权限。wakeGroupMember 可以直接唤醒同群中正在睡眠、未暂停且未禁言的 AI，不能用于绕过暂停。恢复工具的 triggerReply 默认 false；true 只安排一次思考，不保证发言，也不会在发言后自动暂停；此参数不改变恢复授权范围。任何授权都不能借用用户的群主或管理员角色。

每次交接严格按顺序：

1. 暂停上一位 AI，保存已完成的发言及下一位。
2. 白天公开发言时，在其他玩家仍暂停时通过普通消息说明发言要求和下一位姓名，不带 mentionIds，也不用 @ 或成员链接。夜间具体行动要求只写在对应玩家可见的私密消息里，公共消息不点名行动者，也不公布其座位。
3. 若下一位是 AI，调用 resumeGroupAutoReply(senderId=该成员, triggerReply=true)，成功后结束本次任务，不追加群消息，不重复触发。若是人类，等待其发言，不轮询。
4. 收到当前玩家的一条完整发言后，先暂停该 AI，再记录并推进。若人类发言是否结束不明确，等其明确结束，不抢走发言权。

只保持主持人和当前发言 AI 接话。主持人的消息也会触发所有未暂停的玩家，所以先公告后恢复；@ 能触发已暂停成员，不能用 @ 作为展示名字的方式。调用恢复后没有立即得到回复不等于失败，不反复唤醒。

给玩家的公共约定：轮到自己只发一条完整发言，之后结束任务；不自行调用接话调度工具，不抢答，不通过日志、数据库、共享记忆、其他会话或工具探查别人身份。主持人不把底牌推理透露给玩家。

## 夜晚

夜间先暂停全部玩家。按本局规则安排狼人、预言家、女巫等行动，不把行动顺序变化误报成身份信息。

用普通文本发布“天黑请闭眼，狼人请睁眼”等通用口令。禁止公开催促某人查看狼人卡、查验卡或用药卡；具体提醒只发给有权查看的人，再用恢复工具触发对应玩家。具体谁正在行动、谁尚未提交不能公开。狼队先在私密可见范围内讨论，再按本局约定通过行动卡提交狼刀目标；不以公开发言代替私密讨论。

- 为行动者发送限定 audience 的选择卡，含主持人和有权知道该行动的人；interaction.actors 仅含实际行动者，主持人不代投。狼人共同决策可用狼人和主持人可见的独立卡，先约定一致票、队长裁决或平票重选方式。
- 夜间行动的个人选择至少对主持人与有权知道该行动的人开放，确保主持人能读取目标，而不只有汇总；需要收集中提前读取时把主持人列入 visibilityImmediateActors。观众是否能看由开局约定决定；公开投票的权限配置不能直接复用到夜间秘密行动。
- 使用单个 submit 按钮加 selection.mode=single 和合法目标 options；设置 allowChange=false，明确 completion，非强制技能提供“不使用”。目标与药品次数按本局规则限制，不能把已死亡玩家或无效技能作为有效选项。
- 提交按钮 notifyAi=false，注册 callbackEvents=[complete]；多人行动需要依次调度时注册 [vote, complete]。completion 明确覆盖实际行动者全部提交；不以发卡、口头回答或恢复接话代替行动完成。回调仅给发起主持人，不生成公共提交消息，不重复扣药或结算。
- 发布卡片时玩家仍暂停，再仅恢复需要行动的 AI 并 triggerReply=true；卡片说明要求读取并点击交互卡，禁止在群里说目标。收到回调先暂停行动者，然后读取其合法可见结果、保存并推进。
- 预言家查验用另一张仅主持人与预言家可见的卡给结果。女巫仅获得规则允许的信息，不能收到全体身份或其他人的行动。
- 同夜所有行动收齐后统一计算死亡及技能连锁；按规则决定是否先处理猎人等技能，再判断胜负。天亮只公布应公开的死亡与遗言信息。

## 白天投票

分别明确本轮目的、候选名单、投票资格、能否改票和弃票、结束条件及平票处理。上警登记、警长选举、放逐投票是不同阶段，不能把同一张卡或同一份参与者名单直接沿用到下一阶段。

- 上警登记：仅符合资格的玩家选择“上警”或“不上警”，观众不参加。登记收齐后公开上警名单，按约定处理退水、竞选发言，再创建警长选举卡；登记统计不能直接当作警长选举结果。
- 警长选举：actors 填实际有选举权的人，options 填最终候选人；候选资格和选举权按本局规则分开，不把所有群成员当成选民。无候选人或仅一位候选人时按约定直接处理，不虚构无人可投的卡片。
- 放逐投票：通常在存活玩家发言完成后收集，由本局规则确定 actors、候选人、弃票和平票。存在警长加权等票权时，用有权查看的 choices 按记录的权重计票；summary 的人数分布不是加权票数，不直接当作最终票权结果。

公共投票卡省略 audience，使玩家和观众都能看到卡片；interaction.actors 只含本轮实际投票者，观众只看结果，不显示或要求其操作。单个 submit + selection 单选合法候选人；允许弃票时加独立选项。按约定设置 allowChange，通常投下即锁定；completion 为 submittedCount 等于本轮 actors 的人数。

投票过程默认互相保密、结束后公开票型：visibility=public、visibilityTiming=onComplete，summaryVisibility=public、summaryVisibilityTiming=onComplete。主持人需要收集具体票面以处理票权等规则时，将主持人列入 visibilityImmediateActors；其汇总本身随时可读。只对明确允许提前观战的人设置 visibilityImmediateActors 和 summaryVisibilityImmediateActors，不能把人类玩家一并列为观众。仅允许看实时汇总的观众只配置后者。配合 views 的 when 展示已授权数据；不要一律限制为 completed，导致允许实时查看的观众也无法看到结果。

投票按钮 notifyAi=false，注册 callbackEvents=[vote, complete]。依次只恢复一位 AI 投票，实时回调后暂停，再交给下一位；人类正常点击。不要让所有 AI 同时恢复，不播报过程中的未公开票面、票数或提交顺序；通过 readInteractiveMessage 获取真实进度，不用聊天中的口头投票替代工具提交。需要提醒某人时只向该人和有权查看的主持人发送提醒，不把实时回调重新转发成群系统消息。

收到 complete 且正常完成后，确认最后一位 AI 已暂停，读取真实结果、记录结算，再公布应公开的票型，处理平票、出局、遗言和死亡技能；实时事件已经暂停过的成员不重复调度。不能为了推进强制关闭缺票的卡片提前揭晓；人员退出或拒绝投票时请用户决定调整规则或终止。重投建立明确的新轮次；资格或候选名单变更时先更新定义并核对新轮状态，不能重复累计上一轮的票。

## 结束、暂停和续局

- 每次有效死亡结算后按本局规则判断胜负；胜负确定就结束，不再触发玩家。
- 结束时关闭未完成的行动卡，公布结果，并按开局记录恢复原来的接话状态，恢复用 triggerReply=false；不要把本来就暂停的 AI 全部开启。先发结束公告，再恢复，避免集中触发回复。
- 用户中途暂停时暂停玩家，保留卡片与当前阶段，不安排定时轮询。续局先读记录，确认未完成者，再恢复该成员；不要重新分配身份。
- 主持人只能保证按工具反馈推进，不能宣称模型必然遵守发言纪律。发现抢话或重复提交，先核对记录，不凭印象重开整局。

## 卡片格式参考

复杂投票或行动卡需要示例时，通过 listSkills/readSkill 读取“交互消息工具使用指南”，实际操作仍直接调用交互消息工具，并以当前工具 schema 为准；指南中的通用按钮结果回调不能套用到固定选项投票。身份通知用限定可见的普通消息；主持记录卡不需要 shared interaction，使用 acknowledge 按钮即可；投票与行动卡才配置 interaction。所有按钮提供 id、label、action、repeatable。禁止把秘密塞进公共卡片的 definition、按钮 value 或共享初始 state：隐藏统计入口不是隐藏数据。
