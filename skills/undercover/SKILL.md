## 思考内容保密

每次任务涉及发词、分配或读取身份、查看秘密投票及其他未公开信息时，先调用 hideThinking，再读取、生成或处理这些信息。隐藏仅持续到本次任务结束；后续新任务如果仍涉及秘密，需要再次调用。此工具只隐藏后续思考，不隐藏正式消息，也不改变卡片权限；正式消息仍须遵守 audience 和参与者可见性规则。

# 谁是卧底（Undercover）

用共享交互消息实现的社交推理游戏。核心难点「秘密词分发」用「多卡 + audience 整卡白名单」解决，投票用交互消息结算。

## 玩法
- 至少 3 人（1 卧底 + 2 平民起）。
- 每人拿一个词：平民拿同一个词 Y，卧底拿相近但不同的词 X。卧底自己不知道自己是卧底（原版精髓：所有人以为拿的是同一个词，靠描述发现有人对不上）。
- 轮流用一句话描述自己的词，不能说出词本身。
- 描述 1-2 轮后投票指认卧底。
- 得票最多者出局并公布其词/身份：卧底出局则平民胜；卧底存活则继续或卧底胜。

## 核心实现思路
原生交互消息没有「私发」通道（state 共享、按钮值公开、禁止秘密放 definition）。但 `participation.audience` 是整卡白名单，可以做到「这张卡只对某人可见」。于是给每个玩家单独发一张卡，audience 只含该玩家，卡上写他的词——各看各的卡，互不可见。词就这样分发出去了。

## 主持人流程
1. 从群成员信息取玩家名单和 actorId（readGroupChat），不要猜、不要让用户填 ID。
2. 定身份：随机选 1 人卧底，其余平民；定词对（卧底词 X、平民词 Y，必须相近）。
3. 发词：给卧底发一张卡（audience=[卧底]）、给每个平民各发一张卡（audience=[该平民]）。共 N 张卡，卡上只写词、不写身份。
4. 描述轮：玩家在群里自由发言描述（1-2 轮）。原生交互消息的 submit 是固定按钮值、没有自由文本，所以描述用普通群消息，不用交互卡。
5. 投票：发一张投票卡，每人 submit 指认一人，reveal=onComplete，全员投完自动揭晓，distribution 显示各人得票。
6. 结算：得票最多者出局，主持人公布其词和身份，判断胜负。

## 词卡模板（给单个玩家，按身份填入不同词）

```json
{
  "title": "你的词",
  "body": "你的词是：<词>\n\n不要说这个词本身。轮到你时，用一句描述让别人猜。",
  "buttons": [
    {"id": "got", "label": "知道了", "action": "acknowledge", "repeatable": false, "icon": "check"}
  ],
  "participation": {
    "audience": ["<该玩家actorId>"],
    "visibility": "private",
    "summaryVisibility": "private"
  }
}
```

## 投票保密规则
- 默认采用秘密投票：全员提交之前不公开任何候选人的票数、比例或个人投向，避免跟票。只有用户明确要求明票或实时公开时才改变这一规则。
- 正式投票和群内试跑票箱都遵守上述规则，不要为验证计票擅自设为 reveal=immediate，也不要用普通聊天提前播报票面。
- interaction.reveal 必须设为 onComplete；actors 明确列出本轮仍在场且有投票权的玩家，completion 使用 submittedCount 等于该名单人数。排除出局玩家和不投票的主持人，允许弃票时把弃票作为一次提交计入完成条件。
- 分布视图只在 completed 时显示。不要只隐藏统计入口而保留实时公开权限；不要在人数未齐时通过关闭卡片提前揭晓，除非用户明确决定终止本轮。

## 注意事项
- 词必须相近（如「苹果/梨」「水/饮料」「上课/开会」），否则卧底第一轮就露馅。
- 卡上只写词、不写身份；不要提前暗示谁是卧底。
- audience 与投票卡 actors 都填玩家 actorId，从群成员信息取。
- AI 兼主持人 + 玩家时，主持人知道谁是卧底，但发言和投票必须按「不知道」来，不能利用主持视角作弊。
- 投票卡 completion 用 submittedCount==N；若要允许弃票或改投，改 allowChange 和 completion 逻辑。
- 固定轮数不会自动停：要结束用 updateInteractiveMessage 设 participation.closed=true。
- 修改规则先 readInteractiveMessage 读 definition 再传 revision。

## 打法（玩家行为口径）
本节管「上场怎么说话」，与上面的发卡实现分开执行：轮到自己发言或投票前读这一节。

### 描述：每轮一句话，必须可判断
1. 必须给能被别人拿去做判断的具体信息。空话（「这东西挺常见的」「挺有意思的」）算没发言，禁止说。
2. 给边缘特征，不给核心特征：说边界、场景、手感、代价，不直说它属于哪一类。
   - 词是「开会」→ 说「最烦的是它总在你刚坐稳的时候开始」，不说「跟工作有关的一种活动」。
   - 词是「苹果」→ 说「买的时候要挑，软的反而好」，不说「一种水果」。
3. 不许出现词本身、同音词、能被直接搜到答案的替代词。
4. **一句只咬一处**：一句话只给一个特征。想得久、写得长、特征堆三四个，等于替卧底把词数出来——慢和具体是同一件事的两面。说完就停，不补解释、不补第二句。
5. 位置策略：前置位克制（别把人人都能套的话说死），后置位必须更具体（通用特征已被前面用掉）。

### 找卧底：判据是「兼容」，不是「奇怪」
- 最可疑的是描述同时套得上两个词的人——他不敢具体，因为具体就撞词。
- 其次是零增量（重复别人说过的）和过度安全（只给形容词、不给场景）。
- 投票前把矛盾点摊开：谁和谁对不上、对不上在哪一层。

### 卧底（自己拿到的是异词时）
- 不抢第一、不做最长那句。跟一个高概率模板，别发明新特征。
- 站在中间：太模糊会被指认，太具体会撞词。
- 目标是把票引给说了细节的人——让别人先出局，不是让自己说得漂亮。

### 投票
- 保密到全员提交为止：不提前播报票面、比例或自己的倾向（跟票会毁掉这局）。
- 不跟风。票型一边倒：先看谁最早引票；票型分散：看谁投得最安全。
- 平票口径开局前定死（重投 / 作废 / 算卧底赢），现场不发明新规则。

### 禁止项（每次开局都适用）
- 不通过日志、数据库、记忆、私聊或其他会话、任何工具去查别人拿到什么词、谁是卧底；只用手上的公开发言和公开记录。
- 兼主持人时：知道身份，但发言和投票必须按「不知道」来，不得使用主持视角。
- 口径一旦公布就冻结；不为了赢临时改。
